# 画面構成案 — 繋がるクラフト・プラットフォーム

3階層のユーザー(マスター管理者・クライアント・エンドユーザー)ごとに、
「探す・応募する・買う・相談する」がマニュアルなしで完結する画面構成とする。
すべてモバイルファースト(PWA)。本部管理画面のみPC利用も想定し、md以上でサイドバー表示。

エントランス `/` はプロトタイプ用のロール選択画面
(本実装では Firebase Auth ログイン + ロール自動振り分けに置き換え)。

---

## 1. マスター管理者(本部)`/admin`

> 目的: 100社超のクライアントの状況を一望し、案件発行・一斉通知・売上管理を1画面から行う。
> ナビ: PC=左サイドバー / モバイル=下部タブ(ホーム・顧客・案件・チャット・メニュー)

| ルート | 画面 | 主な要素 |
| --- | --- | --- |
| `/admin` | ダッシュボード | KPIカード(クライアント数・進行中案件・今月売上・未読)/ 対応が必要なこと(未処理注文・確認待ちタスク)/ 最近のチャット / 直近の予約 |
| `/admin/clients` | 顧客一覧 | 検索ボックス / ステータス絞り込み / クライアントカード(生徒数・プラン・契約状態) |
| `/admin/clients/[id]` | 顧客詳細 | プロフィール / 契約情報 / 応募中案件 / 最近の注文 / チャットへの導線 |
| `/admin/projects` | 案件管理 | タブ(募集中・進行中・完了)/ 案件カード(応募数)/「案件を作成」ボタン |
| `/admin/projects/new` | 案件作成 | タイトル・カテゴリ・報酬・締切・説明の入力フォーム / 公開時にプッシュ通知を送るトグル |
| `/admin/projects/[id]` | 案件詳細 | 応募クライアント一覧(採用/見送り操作)/ 関連タスクの進捗 |
| `/admin/messages` | チャット一覧 | クライアント別スレッド + グループ / 未読バッジ |
| `/admin/messages/[id]` | チャット | LINE風トーク画面(入力・送信可) |
| `/admin/orders` | 受注・発注管理 | B2B2Cパイプライン(注文受付→自動発注→発送→完了)/ ステータス更新ボタン |
| `/admin/payments` | 報酬・支払管理 | 今月の売上サマリー / 案件ごとの支払一覧(請求済・支払済)/ Stripe手数料3.6%の控除表示 |
| `/admin/announcements` | 一斉通知 | 配信先選択(全クライアント等)+ 本文入力 + プッシュ送信 / 配信履歴 |
| `/admin/settings/visual` | ビジュアル管理 | ノーコード編集(ヒーロー文言・キャンペーンバナー・おすすめ商品)+ ライブプレビュー |
| `/admin/menu` | メニュー(モバイル用ハブ) | 受注・発注 / 報酬・支払 / 一斉通知 / ビジュアル管理 / エントランスへ戻る への入口 |

## 2. 管理者=クライアント(インストラクター)`/client`

> 目的: 「本部に相談する・案件に応募する・生徒に発信する・商品を仕入れる」を日常動線に。
> ナビ: 下部タブ(ホーム・案件・タスク・チャット・メニュー)

| ルート | 画面 | 主な要素 |
| --- | --- | --- |
| `/client` | ホーム | あいさつ+教室名 / 本部からのお知らせ / 期限が近いタスク / 応募中案件のステータス / クイックアクション(Zoom予約・本部に相談・仕入れ) |
| `/client/projects` | 案件一覧 | タブ(募集中・応募済み)/ 案件カード(報酬・締切・カテゴリ) |
| `/client/projects/[id]` | 案件詳細・応募 | 案件内容 / 「この案件に応募する」→ 応募完了(モック) |
| `/client/tasks` | タスク管理 | ステータス別(未着手・進行中・確認待ち・完了)/ 修正依頼・Zoom予約・素材提出の進捗が一目で分かる |
| `/client/messages` | チャット一覧 | 本部スレッド(最上部固定)/ 生徒スレッド / グループ |
| `/client/messages/[id]` | チャット | トーク画面(入力・送信可) |
| `/client/students` | 生徒管理 | 生徒一覧(最終注文・累計購入額)/ 一斉メッセージ導線 |
| `/client/students/[id]` | 生徒詳細 | プロフィール / 購入履歴 / チャット導線 |
| `/client/shop` | 仕入れ(卸)| 商品カタログ(卸価格・利益率表示)/ 数量選んで発注(モック) |
| `/client/booking` | Zoom予約 | Googleカレンダー連携の空き枠表示(モック)→ 枠選択 → 予約完了 |
| `/client/menu` | メニュー | 生徒管理・仕入れ・Zoom予約・お知らせ履歴・プロフィール・設定への入口 |

## 3. エンドユーザー(生徒・一般顧客)`/user`

> 目的: メルカリ/Amazonのように迷わず「見る・買う・聞く」ができる。
> ナビ: 下部タブ(ホーム・ストア・注文・メッセージ・マイページ)

| ルート | 画面 | 主な要素 |
| --- | --- | --- |
| `/user` | ホーム | 教室(先生)カード / 先生からのお知らせフィード / おすすめ商品カルーセル / 体験レッスン誘導バナー |
| `/user/shop` | 商品カタログ | カテゴリタブ / 商品グリッド(NEW バッジ) |
| `/user/shop/[id]` | 商品詳細 | 商品説明 / 価格 / 「カートに入れる」(トースト表示) |
| `/user/cart` | カート・購入 | 数量変更 / 合計 / 「購入する」→ 決済デモ(Stripe想定)→ 注文完了 |
| `/user/orders` | 注文履歴 | 注文カード + 配送ステータスの進捗バー(注文受付→発注→発送→完了) |
| `/user/messages` | メッセージ | 先生とのトーク / 教室グループ |
| `/user/messages/[id]` | チャット | トーク画面(入力・送信可) |
| `/user/mypage` | マイページ | プロフィール / プッシュ通知設定 / ホーム画面追加の案内 / ヘルプ |

---

## 主要ユーザーフロー

1. **案件応募**: 本部が `/admin/projects/new` で発行(+プッシュ通知)→ クライアントが `/client/projects` で発見 → 詳細で応募 → 本部が `/admin/projects/[id]` で採用 → タスク化され `/client/tasks` で進捗共有。
2. **B2B2C注文**: 生徒が `/user/shop` で購入(Stripe決済)→ 自動で本部へ仕入れ発注 → 本部が `/admin/orders` でステータス更新 → 生徒は `/user/orders` で追跡、クライアントには手数料マージン。
3. **Zoom予約**: クライアントが `/client/booking` で本部の空き枠(Google Calendar)から選択 → カレンダー登録 & Zoomリンク発行 → 双方に通知。

## デザイン原則

- ブランドカラー: テラコッタ `#d9634a`(`bg-brand` / `text-brand` / `bg-brand-soft`)。背景は `--color-cream`。
- 角丸大きめ(`rounded-2xl`)・カード基調・影は控えめ。絵文字をアイキャッチに活用。
- 本部画面のアクセントはインディゴ、エンドユーザー画面はブランド色。
- タップ領域は44px以上。下部タブは `safe-area-inset-bottom` に対応。
