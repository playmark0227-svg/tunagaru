# 画面構成案 — つながるCraft プラットフォーム

## 基本思想

- **囲い込み**: HP制作で繋がった顧客が、その後も開き続けたくなる「デジタル系総合相談窓口」
- **脱SNS管理**: LINE/メッセンジャーに分散したやり取りを廃し、全タスクをアプリ内で完結・可視化
- **転記忘れゼロ**: チャットのメッセージをワンタップでタスク化 (将来はAIが会話から自動抽出)

3階層の権限 (**マスター=本部 / 作業者=スタッフ・クリエイター / クライアント**) に、
物販B2B2C用の**エンドユーザー**を加えた4つの視点を最適化する。
すべてモバイルファースト(PWA)。本部管理画面のみPC利用も想定し、md以上でサイドバー表示
(レスポンシブでボタン配置・表示項目を切替)。

エントランス `/` はプロトタイプ用のロール選択画面
(本実装では Firebase Auth ログイン + カスタムクレームのロールで自動振り分け)。

## 1.5 作業者(スタッフ/クリエイター)`/worker`

> 目的: 募集中の新規案件をInstagram感覚で発見・応募し、担当案件のタスクを見落とさない。
> ナビ: 下部タブ(フィード・タスク・チャット・マイページ)

| ルート | 画面 | 主な要素 |
| --- | --- | --- |
| `/worker` | 案件募集フィード | Instagram風の投稿カード(カバー・いいね・保存・応募)/ カテゴリ絞り込みチップ |
| `/worker/projects/[id]` | 案件詳細・応募 | 募集内容 / 報酬・締切 / 自分の担当タスク / 応募ボタン(確認→完了) |
| `/worker/tasks` | 担当タスク | **案件ごとにグルーピング** + カテゴリバッジ / 発生源バッジ(チャットから・AI抽出) |
| `/worker/messages` | チャット一覧 | 本部直通(固定)+ **案件ごとの専用グループ**(カテゴリバッジ) |
| `/worker/messages/[id]` | チャット | トーク画面 + メッセージの📋タスク化ボタン / ヘッダーから案件詳細へ |
| `/worker/mypage` | マイページ | プロフィール(得意分野タグ・実績)/ プッシュ通知設定 |

### 📱 案件募集フィードのコンポーネント構成(詳細)

```
WorkerFeedPage (/worker)
├── FeedHeader             ロゴ + 「案件フィード」 + 通知ベル(バッジ)
├── CategoryChips          すべて / 動画制作 / HP制作 / デザイン / SNS運用 / …
└── FeedCard[]             1案件 = 1投稿 (createdAt降順)
    ├── CardHeader         投稿者(本部)アバター・投稿日・カテゴリバッジ
    ├── CoverVisual        グラデーション+絵文字カバー / 報酬ピル(¥45,000)オーバーレイ
    ├── ActionRow          ♥いいね(カウント) / 保存 / 「詳しく見る」ボタン
    └── Caption            タイトル(太字) + 説明2行省略 + 締切・応募数メタ
```

- 本実装: `projects` コレクションの `forWorkers=true & status=open` を無限スクロール取得。
  いいね/保存は `users/{uid}/reactions` に保存し、新着投稿は FCM トピック `workers` へプッシュ。
- 応募フロー: 応募確定 → `projects/{id}/applications` 作成 → 本部へ通知 →
  採用時に**案件専用チャットグループが自動作成**され、以後のやり取り・タスクが案件単位に集約。

### 🗂️ 案件種別ごとのチャット・タスク画面のコンポーネント構成(詳細)

```
MessagesPage (全ロール共通パターン)
├── PinnedThreadCard       本部直通スレッド (最上部固定・「本部」バッジ)
├── ProjectGroupSection    ★案件ごとの専用グループ
│   └── ThreadRow[]        アバター + グループ名 + カテゴリバッジ(動画制作/HP制作/…)
│                          + 最終メッセージ + 未読バッジ
└── DirectSection          個別トーク (クライアント別 / 生徒別)

ChatRoom (トーク画面)
├── ThreadHeader           相手名 + カテゴリバッジ + 案件詳細へのリンク(💼)
├── MessageBubble[]        LINE風の吹き出し
│   └── TaskifyButton      ★受信メッセージ横の📋 → ワンタップでタスク化 (source: "chat")
└── InputBar               テキスト入力 + 送信

TasksPage (案件種別ごとに整理)
└── ProjectTaskGroup[]     ★案件単位のカード
    ├── ProjectHeader      絵文字サムネ + 案件名 + カテゴリバッジ + 完了数(2/5)
    └── TaskRow[]          タスク名 + 状態バッジ(未着手/進行中/確認待ち/完了)
                           + 期限 + 発生源バッジ(チャットから/AI抽出/EC連携)
```

- 「ホームページ修正」「動画制作」「パンフレット作成」の話題が**スレッドもタスクも案件単位で分離**され、混ざらない。
- タスクの発生源 (`source`) を可視化することで「転記忘れ」の発生箇所を潰す。
  Phase 3 ではAIが全チャットを走査してタスク候補を自動提案する(本部ダッシュボードの朝ダイジェスト参照)。

## 主要ユーザーフロー

1. **案件応募 (クライアント向け)**: 本部が `/admin/projects/new` で発行(+プッシュ通知)→ クライアントが `/client/projects` で発見 → 詳細で応募 → 本部が `/admin/projects/[id]` で採用 → タスク化され `/client/tasks` で進捗共有。
2. **案件応募 (クリエイター向け)**: 本部がモニター募集等を投稿 → 作業者が `/worker` のフィードで発見・いいね・応募 → 採用 → 案件専用グループ(チャット)とタスクが自動作成 → `/worker/tasks` で進捗管理。
3. **B2B2C注文**: 生徒が `/user/shop` で購入(Stripe決済)→ 自動で本部へ仕入れ発注 → 本部が `/admin/orders` でステータス更新 → 生徒は `/user/orders` で追跡、クライアントには手数料マージン。
4. **Zoom予約**: クライアントが `/client/booking` で本部の空き枠(Google Calendar)から選択 → カレンダー登録 & Zoomリンク発行 → 双方に通知。
5. **EC売上→発送 (Phase 3)**: BASEの売上webhook → `/admin/orders` の EC通知パネルに集約 → ワンタップで発送タスク作成 (`source: "ec"`)。

## デザイン原則 — 「ブループリント」

- **角張った直角基調 + 細いヘアライン枠 (1px)**。カード・バッジ・ボタン・入力欄はすべて角形 (`rounded-none`〜`rounded-sm`)。
- **アクセントは水色 `#17b6d4` (`--color-aqua`)** を線・小面積で効かせる: アクティブタブのインジケータ、見出しのアンダーバー、Phase 3 要素の細枠グロー (`.sticker-glow`)。
- ベース: ロゴのネイビー `#282f5a` (`bg-brand`) + インク `#1c2233`。グレーはすべて `text-ink/40〜80` の透明度スケールで統一。
- 背景は淡いブループリント方眼 (`--color-cream` + 極薄グリッド)。
- フォント: 角ゴシック **Zen Kaku Gothic New** / 数字・金額は **Space Grotesk** (`.font-display`)。
- 影は `shadow-sm` まで。装飾はHUDコーナー (`.hud-corners`) など線的な要素のみ。
- タップ領域は44px以上。下部タブは `safe-area-inset-bottom` に対応。
